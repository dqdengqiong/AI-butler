# AI个人管家项目需求分析文档

## 一、项目概述

AI个人管家是一款基于多 Agent 架构的个人成长管理系统。

目标是从传统问答式 AI 升级为长期陪伴用户成长的 AI 伙伴。系统提供可自动归档和恢复的多会话聊天；每个会话内部再通过上下文分段和受控长期记忆保持连续性。

第一阶段重点：以学习和职业成长场景切入，优先实现公务员备考 Agent。

## 二、产品定位与目标

产品定位：帮助用户制定目标、拆解路径、执行计划，并持续记录成长过程。

核心目标：

1. 明确用户目标
2. 生成个性化规划
3. 提供可靠资料
4. 跟踪任务执行
5. 在不增加记忆管理页面的前提下保持长期沟通连续性

## 三、产品形态

1. 第一阶段：微信小程序 + H5
2. 第二阶段：基于 uni-app 发布 iOS 和 Android 应用
3. 第三阶段：形成完整 AI 个人操作系统

前端采用 uni-app（Vue 3 + TypeScript），适合快速覆盖多端。

## 四、整体产品结构

首页就是单一聊天入口，不提供“新建对话”。用户直接表达需求，服务端在发送时自动延续、恢复或归档并建立新场景；专业 Agent 快捷入口始终可见，处理结果由大管家统一整理、追问和确认。

MVP 页面结构固定为：

1. 首页：聊天、Agent 快捷入口与多会话历史
2. 头部“计划”：独立计划、跨计划任务和执行状态
3. 头部“设置”：提醒、隐私和数据设置

学习类 Agent：

- 公考 Agent
- 雅思 Agent
- 编程学习 Agent

职业类 Agent：

- 求职 Agent
- 简历 Agent
- 职业规划 Agent

生活类 Agent：

- 健康 Agent 等

## 五、公考 Agent 需求

核心流程：

```text
用户目标输入
  → 用户信息采集
  → 资料检索
  → 学习路线规划
  → 来源审核
  → 用户确认
  → 每日任务执行
  → 阶段总结
```

功能：

1. 备考准备：考试资料、学习路线、资料推荐
2. 日常执行：任务提醒、打卡、反馈
3. 阶段总结：计划完成情况分析和调整

暂不实现：

- 成功率预测
- 能力评分模型

## 六、用户端功能

主要页面：

1. 首页：展示计划总览、管家状态和今日任务
2. 计划：按计划查看任务，也可汇总查看跨计划任务；任务打卡可直接操作
3. 聊天：与大管家沟通目标、查询资料、新建计划和调整计划
4. 我的：管理提醒、隐私和数据设置

交互约束：

- 手机号是唯一账号键，内部资源仍使用 UUID；H5 只提供手机号登录，微信小程序只提供微信登录并强制申请授权手机号。短信验证由服务端配置，默认关闭。
- 每个用户最多一个未删除的 `CURRENT` 会话。结构化流程优先延续；明显新目标在置信度至少 `0.85` 时自动归档，模糊输入必须确认；路由不可用时延续当前话题。
- 已归档会话支持查看、续聊和软删除；查看不改变状态，发送时才原子恢复。空白欢迎态不写入历史。
- 快捷入口由服务端目录驱动。首期考公为 `AVAILABLE`，雅思、求职为 `COMING_SOON`；未开放入口不得创建会话或 run。
- 专业 Agent 入口始终展示；没有未完成任务时进入临时欢迎态，用户发送第一条消息后才创建场景。
- 客户端只提交公开 `specialist_code`，不接触 `user_agent_id`。专业会话固定路由，不能在会话内静默切换领域。
- 上下文接近模型预算时，系统在后台压缩并归档当前分段、轮换 LangGraph 线程；归档过程不删除消息，也不改变聊天页面。
- AI 管家可从用户明确表达的低风险偏好、习惯、约束和背景中提取跨分段长期记忆，但不提供设置入口、列表、开关或公开管理 API。
- 用户可以通过聊天明确更正或遗忘长期记忆；遗忘不等同于删除原聊天记录。
- 用户可同时拥有多个独立计划；一句话包含多个同领域子目标时，可形成一个组合计划草案并整组确认。
- 调整已有计划时，一次只能选择一个目标计划。其他计划仅用于负荷校验，不得被联动修改。
- 计划创建和调整的最终批准只能通过带审批 ID 和版本的结构化按钮完成；聊天文字“确认”不直接产生副作用。

## 七、MVP 范围

必须实现：

- 用户系统
- AI 管家入口
- Agent 管理
- 公考 Agent
- 资料检索
- 规划生成
- RAG 回答编号引用与来源详情
- 任务管理
- 多会话历史持久化，以及会话内部自动上下文分段与智能压缩
- 跨归档分段的受控长期记忆

MVP 只开放公考 Agent。雅思、求职和健康入口如保留在概念原型中，必须标记为“即将开放”或“概念演示”，不能进入真实的计划创建成功流程。

暂不开发：

- 健康管理
- 财务管理
- 复杂预测模型
