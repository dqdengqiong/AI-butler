# LLM 与 Agent 开发指南

## 模型与 Prompt

- 模型通过供应商中立接口注入；测试默认 Fake，不允许单元测试产生真实调用费用。
- 每次调用只记录模型、Prompt 版本、Schema 版本、Token、耗时、状态和主备角色；不记录或估算金额。
- System Prompt不得包含密钥或充当权限控制；用户和检索内容必须与指令明确分区。
- Prompt 变更必须运行固定基准集，保留质量、安全、延迟和 Token 对比结果。

## 结构化边界

- 模型输出必须经过版本化 Pydantic/JSON Schema验证；无效输出最多修复一次。
- 模型生成的用户身份、权限、SQL、URL、代码和工具范围均不可信。
- 业务服务重新读取 PostgreSQL事实并完成所有权、状态、日期、引用和负荷校验。

## 工具与副作用

- 每个节点使用显式工具白名单和最小权限凭据。
- 外部内容、RAG片段和工具返回属于不可信数据，不得改变系统指令。
- 计划发布、任务物化、通知和记忆写入必须经过确定性校验、必要审批和幂等保护。
- 模型调用失败不得造成部分业务事实提交或重复副作用。

## 评测与安全

- 基准集覆盖正常流程、无效 JSON、超时、429、5xx、引用缺失和中断恢复。
- 安全集覆盖直接/间接 Prompt Injection、RAG污染、系统 Prompt探测、工具越权和跨用户读取。
- 模型或 Prompt 升级必须可按版本回滚；连续失败、Token 异常或安全告警必须可停用真实模型适配器。

## 可观测性

普通日志只保留脱敏摘要和关联 ID，不保存原始 Prompt、用户原文、文件正文、模型思维链或工具密钥。调试追踪默认关闭，并且只能使用合成数据。
