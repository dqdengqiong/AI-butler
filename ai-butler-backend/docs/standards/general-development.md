# 通用开发规范

## 规则级别

- MUST：合并前必须满足。
- SHOULD：默认遵守，偏离时必须记录原因。
- MAY：按场景选择。

## 基础约束

- 文档使用简体中文，代码、路径、配置名和提交类型使用英文。
- 文件 MUST 使用 UTF-8、LF 和末尾换行；禁止提交编辑器缓存、构建产物和密钥。
- 依赖 MUST 通过锁文件固定；新增依赖必须说明必要性、许可证与安全影响。
- 配置 MUST 从环境读取并由类型化 Settings 校验；不得散落读取环境变量。
- 时间 MUST 以带时区 UTC 存储，API 使用 ISO 8601；主键默认 UUID。

## 错误与日志

- 领域错误与基础设施错误必须分层，API 只能返回稳定错误码和安全文案。
- 禁止吞掉异常；可重试错误必须保留原因、attempt 和关联 ID。
- 结构化日志至少包含 `request_id`、`run_id`、`thread_id` 或 `worker_id` 中适用的字段。
- MUST NOT 记录访问令牌、流票据、密钥、手机号、用户原文、文件正文、系统 Prompt 或模型思维链。

## 安全与隐私

- 输入必须校验长度、格式、所有权和权限；数据库查询必须参数化。
- 用户数据访问 MUST 带服务端生成的 `user_id` 条件。
- 外部内容按不可信数据处理，不得直接成为指令、SQL、URL 或工具参数。
- 本地、测试和生产凭据必须隔离，测试不得使用真实用户数据。

## 评审

- 评审优先检查正确性、安全、数据一致性和恢复能力，再检查风格。
- 复杂行为 SHOULD 通过清晰命名和小函数表达，并 MUST 按[代码注释规范](./code-comments.md)记录设计原因、边界与风险；注释不得复述代码。
- TODO 必须包含负责人语义或追踪编号，不得用 TODO 掩盖验收缺口。
